== What

The leftovers of link:question-loop-verification.adoc[`question-loop-verification`]. That package measured every item Q1 to Q7 and R1 to R4 at smoke scale (3 runs, 2 fixtures), so every verdict reads _not at the specified scale_ (link:../../../plan-marshall-documentation/doc/specification/evaluation.adoc#results[Evaluation Reference, Results] and its limits). The mechanisms are described in link:../../../plan-marshall-documentation/doc/developer/question-loop-experiment.adoc[The Question-Loop Experiment]; the code is kept on the pushed branch `verification/question-loop-experiment` of this repository (`488ce47`). This package turns the durable parts of that code into maintained code, settles what the smoke run left open, and repeats the measurement at the revised scale of <<scale>>, with the criteria of the original package except where the operator changed them before the first run (task 2 and <<scale>>). The criteria are fixed before the first measured run and not changed by it: a criterion change is decided by the operator before the first run of the follow-up, on reasons not drawn from the follow-up's own runs, and recorded in this package (<<decisions>>).

* _Evidence._ Every run's evidence — `runs.jsonl`, `invocations.jsonl`, the stub logs, the per-invocation archives and the answer audit — is kept and pushed outside any plan worktree: on the branch `question-loop-follow-up` of the private repository `cuioss/plan-marshall-telemetry`, beside the scenarios kept on that repository's branch `verification/question-items`, before the plan's worktree is removed. A published figure whose source is not in that store is not a result.

* _Fixtures per item._ Q1 to Q7 and R3 run on 2 fixtures each — the count of the smoke scale, held so that the two scales compare item by item — where Q1 to Q5 and R3 take the loop tasks of the corpus topic `question/apply-answer`, Q5's bound tasks come from `question/ask-or-proceed`, Q6 takes the quorum fixtures of the two vote links, Q7 takes the fixtures of Q2 on Claude Code only, and the original descriptions are the controls of Q2. R1 and R2 run on the probe, R4 runs on the probe for small work and on the two scenarios named in task 10 for large work. Task 6 states the resulting invocations per item and host before the first run.

The run costs differ by orders of magnitude and are planned with that in mind (task 6): OpenCode runs are cheap (60 runs of R3 cost 0.22 USD), Claude Code costs dollars per invocation of 24 runs (about 2.3 to 2.9 USD), Antigravity reports no figures; the wall time is the cost of R1 (6.6 h for 12 OpenCode runs) and R2 (9.3 h for 24 runs).

[#scale]
== Scale and Criteria

The measurement is decision-driven, not scale-driven: it runs only as much as the values it settles need (`headless.resumability`, the `questions` values of the shipped roles, the question bound). The revised scale, decided by the operator on 2026-10-28 before the first run (<<decisions>>), replaces the scale the original package specified:

* _Base._ 3 runs per fixture, host and form (warm and fresh), the scale of the smoke run, with the driver defects fixed, so that the mechanisms are confirmed and every figure has durable evidence.
* _Criterion._ The rate thresholds of the original package (at least 95 % for Q1, Q2's asks, Q4, R1 and R2; at least 90 % for the second ask of Q5) are testable only at about 20 runs. They become "every run of the group passes". A group whose runs disagree (some pass, some fail) is extended to 10 runs and reported with its rate; a group whose runs all agree is not extended. A value is shipped only for a duration, bound or rule at which every run passed. The clauses that were already "every run" or "no run" (Q2's no-host-tool and no-guess clauses, Q3, Q5's bound clause, Q6, Q7, R3) and R4's missing criterion are unchanged.
* _Q5, the question bound._ Sequential: the shipped `3` runs first; if no run reached the bound, `3` stays and the candidates `4` and `5` are not run; only where a run reached it, `4` runs, then `5`.
* _R1 and R2, hold and resume._ Longest first: the cap (a 3,600 s hold; a resume after 1 h) runs first per host; where every run passes, that duration is the host's value and the shorter durations are not run; where one fails, the measurement descends through 30, 15 and 5 min until one passes. R2 stays at 1 h at most.
* _Statement._ A verdict is stated with the number of runs behind it and the client version, never as "passed at the specified scale"; a rule of the form "no run reached the bound" is stated with the pooled count it rests on. The client version (the version each run's output names, or the version probe where it names none) and the model are recorded for every run and published with every value, so that a settled value carries the version range it was measured on.
